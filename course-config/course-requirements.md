# 操作系统实践课程要求

本文依据课程发放的《05-学生须知》整理。遇到后续增量包或 V2 实验说明书的新约定时，以当轮说明书和预置接口为准；本仓库的 [`lab0-v2-requirements.md`](lab0-v2-requirements.md) 与 [`lab1-v2-requirements.md`](lab1-v2-requirements.md) 记录了新版要求的具体对照。

## 成绩与验收

- 现场验收占总评 70%：lab1 占 10%，lab2 至 lab7 各占 15%。
- 期末考查占 30%：第 14 周闭卷现场设计考查占 10%，第 15 周综合实验报告占 20%。
- 每个实验只有一次正式面对面验收。现场需跑通核心功能、通过回归自检并回答三个问题。
- 功能测试决定成绩上限，问答表现决定最终档位。
- 全学期基础验收统一以单核 `-smp 1` 为准，单核功能完整仍可评 A 档；从 lab4 起可自愿挑战双核并发，每轮独立计算额外 3 分。
- Lab0 不单独计分，三份图会在 Lab1 验收时抽查。若适用任课教师依据竞赛经历作出的免验证认定，则以教师确认的验收通过结果计入实验成绩。

## 代码与工作方法

- 全学期只领取一次个人初始基线。本仓库只采用学号 `2024302111427` 对应的基线。
- 后续实验通过统一增量包叠加到同一代码库，不重新领取完整代码。
- 禁止修改增量包和基线中标明的系统预置文件；它们定义硬件与课程测试的接口边界。
- MIT xv6 仅作原理参考。课程的系统调用号、用户程序加载、诊断输出和个性化参数均可能不同，不能直接复制公开版实现。
- 每轮动手前先写设计笔记，明确数据结构、不变式、错误回滚路径。
- 每轮为自己的实现设计两个测试用例，覆盖边界条件和错误路径。官方测试判断统一规范，自写测试证明个人设计。
- 每轮验收都可能包含早期实验的回归测试；发现前期缺陷应在同一代码库中修复并保留清晰提交历史。

## Git 归档规则

本仓库每轮完成后执行：

```bash
git add .
git commit -m "第n次实验：<本次完成内容>"
git tag labN
```

历史标签使用 `lab0`、`lab1`、`lab2`，不使用日期。提交远程备份时同时推送分支与标签；当某版说明书明确要求 `labN-submit` 时，同时建立并推送该验收标签。本轮 Lab1 同时保留 `lab1` 和说明书要求的 `lab1-submit`，两者指向同一提交。

归档命令：

```bash
git archive --format=zip -o 提交-labN-2024302111427.zip labN-submit
```

## AI 使用边界

课程允许 AI 辅助理解、实现和测试，但本人必须主导设计并能解释个性化参数、数据结构、错误路径及因果关系。Lab0 要求三张图由本人理解并绘制；本仓库使用黑白 PNG 作为展示格式，并保留 Mermaid 源文件，便于复核和后续修正。
